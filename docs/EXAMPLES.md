# Examples

Use two devices. These examples call the command `btfling`. On Windows,
use `.\btfling.exe` and keep `btfling-ble.exe` beside it.

## First run and the TUI

```sh
btfling tui
```

Configuration and keys initialize automatically. Visit Client to see your name
and fingerprint. Press n to change the client name. Tab to Pair on both devices;
each advertises and discovers. Select a nearby device and press Enter on either
end. Its name is learned automatically. Compare fingerprints out of band.

For a source checkout on macOS:

```sh
go run ./internal/buildhelper -out .
go run . tui
```

Keep the command and helper from the same build together.

## Pair from the CLI

Run the same command on each device:

```sh
btfling pair
```

Each advertises and scans; the first available pairing peer is selected. The
commands exchange keys, save the learned names, and exit. Simultaneous initiation
is resolved automatically. This uses first-use trust; compare fingerprints from
`keygen` or `peers` through a trusted channel before sensitive transfers.

To target a particular device instead, leave `pair` running on Bob and discover
him from Alice:

```sh
# Bob
btfling pair
```

```sh
# Alice
btfling discover -timeout 20s
btfling pair BOB_DEVICE_ID
```

Replace `BOB_DEVICE_ID` with the actual 32-character ID from discovery output.
Alice's `pair` also advertises while finding Bob.

## Override a learned name

```sh
# Bob
btfling pair -as alice

# Alice, on her device
btfling pair BOB_DEVICE_ID -as bob
```

The aliases `alice` and `bob` are local conveniences. Without `-as`, the remote
client's name is used. After pairing:

```sh
btfling peers
btfling rename bob work-laptop
```

## Verify a fingerprint before saving

Run `btfling keygen` on both devices and exchange the printed fingerprints through
a separate trusted channel. Then:

```sh
# Bob
btfling pair -trust ALICE_FINGERPRINT

# Alice
btfling pair BOB_DEVICE_ID -trust BOB_FINGERPRINT
```

Replace placeholders with the actual fingerprints and device ID. An optional `-as`
can still be supplied. A wrong fingerprint saves no new trust on that endpoint.
A previously trusted key that changes is rejected even without `-trust`.

## Send a file

Assume each device has the other saved under the aliases shown:

```sh
# Bob waits
btfling receive alice -out report.pdf
```

```sh
# Alice sends
btfling send bob -in report.pdf
```

Either command may start first. Every transfer is encrypted. Choose a destination
that does not already exist; `-out` only publishes a verified complete file.

To reverse the direction:

```sh
# Alice
btfling receive bob -out reviewed.pdf

# Bob, on his device
btfling send alice -in reviewed-report.pdf
```

On Windows:

```powershell
# Bob
.\btfling.exe receive alice -out .\photo.jpg

# Alice, on the other device
.\btfling.exe send bob -in .\photo.jpg
```

## Use binary pipelines

```sh
# Alice
cat message.txt | btfling send bob
```

```sh
# Bob
btfling receive alice > message.txt
```

For arbitrary generated bytes on Unix:

```sh
# Alice
head -c 4096 /dev/urandom | btfling send bob

# Bob, on his device
btfling receive alice -out random.bin
```

Application bytes are not interpreted as text. Shell redirection can leave partial
output on failure; check the exit status. On Windows, explicit file flags avoid
shell-specific native pipeline encoding behavior.

## Set a deadline

```sh
btfling pair -timeout 2m
btfling send bob -in report.pdf -timeout 5m
```

The deadline covers the entire operation. Allow enough time for the conservative
BLE transport. By default pairing/transfers wait indefinitely. Ctrl-C cancels.

A Unix script can check completion:

```sh
if btfling receive alice -out report.pdf -timeout 5m; then
    printf 'Received report.pdf\n'
else
    printf 'Transfer failed; inspect stderr and the destination before retrying\n' >&2
fi
```

## Replace a device key

If a device's key changes, pairing and transfers reject it. Verify the new
fingerprint through a trusted channel, then explicitly forget the old relationship
on both devices before pairing again:

```sh
btfling forget bob
btfling pair BOB_DEVICE_ID -trust BOB_NEW_FINGERPRINT
```

## Use a separate profile

```sh
btfling --config "$HOME/.config/btfling-travel" tui
```

The new profile initializes its own name, device ID, key, and peer list. Do not
copy one active device's private identity to another device.
